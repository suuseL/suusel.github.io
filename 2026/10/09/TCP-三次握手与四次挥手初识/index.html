TCP-三次握手与四次挥手初识

相关标志位和字段

  • SYN（同步标志位）
  • ACK（确认标志位）
  • seq（数据包序列号字段）：32位无符号数。用于标识数据包的顺序，表示该报文段中第一个数据字节在TCP字节流中的序号。
  • ack（数据包确认号字段）：32位无符号数。表示期望对方继续发送的数据包的序列号。

tips：SYN，ACK，FIN这些大写的单词表示标志位，而seq，ack这些小写的单词表示字段。

TCP三次握手流程

  1. 客户端浏览器访问服务端网站时，首先向服务端发送SYN报文段，请求建立连接；
  2. 服务端收到客户端的请求后，生成自己的ISN，并回复SYN-ACK报文段，确认客户端的连接请求；
  3. 客户端收到连接请求后，发送ACK报文段，完成连接建立。

简记

  1. 客户端 -> 服务端：发送 SYN=1，ACK=0 包（请求建立连接）；
  2. 服务端 -> 客户端：发送 SYN=1，ACK=1 包（确认连接请求并发送自身序列号）；
  3. 客户端 -> 服务端：发送 SYN=0，ACK=1 包（确认服务端响应完成连接建立）。

第一次握手

客户端向服务端发送一个 _SYN_（同步）数据包，其中包含客户端的初始 ISN（ISN是一个随机值，用来标识数据包的顺序）。

标志位和字段值

  • SYN=1（表示请求建立连接）
  • ACK=0（表示不携带确认信息）
  • seq=x（客户端随机生成的随机数，如1000）
  • ack=0（因为是第一个报文，尚未收到对方的序列号）

第二次握手

服务端收到客户端的 SYN 报文段后，检查客户端的 IP 和 _**端口 **_是否合法，若合法，则回复 _SYN-ACK_（同步确认）报文段。

标志位和字段值

  • SYN=1（表示同意建立连接）
  • ACK=1（表示确认客户端的SYN）
  • seq=y（服务端生成的随机数，如2000）
  • ack=x+1（客户端的ISN+1，即1001）

第三次握手

客户端收到 SYN-ACK 报文段后，检查服务端的 IP 和 端口 是否合法，若合法，则发送 ACK（确认）报文段。

标志位和字段值

  • SYN=0
  • ACK=1（表示确认服务端的SYN）
  • seq=x+1（客户端的ISN+1，如1001）
  • ack=y+1（服务端的ISN+1，如2001）

TCP四次挥手流程

  1. 客户端完成数据传输后，向服务端发送 FIN 报文段，请求关闭连接；
  2. 服务端收到 FIN 报文段后，回复 _**ACK **_报文段，确认关闭请求；
  3. 服务端完成数据传输后，发送 FIN 报文段，请求关闭连接；
  4. 客户端收到 FIN 报文段后，回复 ACK 报文段，确认连接关闭。

简记

  1. 客户端 -> 服务端：FIN=1，ACK=1（请求关闭连接）；
  2. 服务端 -> 客户端：FIN=0，ACK=1（确认关闭请求）；
  3. 服务端 -> 客户端：FIN=1，ACK=0（请求关闭连接）；
  4. 客户端 -> 服务端：FIN=0，ACK=1（确认连接关闭）；

第一次挥手

客户端或服务端决定关闭连接时，一方发送 FIN 报文段，表示不再发送数据。

标志位

  • FIN=1（表示请求关闭连接）
  • ACK=1（表示确认已接收的数据）
  • seq=当前序列号
  • ack=对方已接收的序列号+1

第二次挥手

对方收到 FIN 报文段后，回复 ACK 报文段，表示已收到关闭请求。

标志位

  • ACK=1（表示确认FIN）
  • seq=当前序列号
  • ack=对方的序列号+1

第三次挥手

被动方完成数据传输后，发送 FIN 报文段，表示请求关闭连接。

标志位

  • FIN=1（表示请求关闭连接）
  • ACK=1（表示确认已接收的数据）
  • seq=当前序列号
  • ack=对方已接收的序列号+1

第四次挥手

主动方收到 FIN 报文段后，发送 ACK 报文段，表示已收到关闭请求。

标志位

  • ACK=1（表示确认FIN）
  • seq=当前序列号
  • ack=对方序列号+1
